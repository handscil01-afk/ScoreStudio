# 수용 테스트

## 프로젝트 파일
1. 새 프로젝트를 만들고 제목을 바꾼다.
2. `.scoreproj`로 저장한다.
3. 앱을 닫고 다시 실행한다.
4. 파일을 다시 열었을 때 제목과 파트가 보존되는지 확인한다.
5. 잘못된 JSON 파일을 열었을 때 앱이 종료되지 않고 오류를 안내하는지 확인한다.

## MUSX 가져오기(향후)
1. 원본 파일을 백업한다.
2. 변환 전 원본의 파트 수, 마디 수, 제목, 가사 유무를 기록한다.
3. 변환 후 같은 항목을 비교한다.
4. 임시표, 붙임줄, 이음줄, 반복기호, 셈여림, 아티큘레이션을 표본 검사한다.
5. 미지원 요소가 있으면 경고로 표시한다.
6. 원본 파일의 수정 시각/내용이 바뀌지 않았는지 확인한다.

## 편집(향후)
- 음표를 입력/삭제한 뒤 저장하고 다시 열어도 음악 정보가 유지된다.
- Undo/Redo가 편집 작업을 정확히 되돌린다.
- 박자에 맞지 않는 입력을 무시하거나 명확히 안내한다.
- 여러 파트의 음표가 서로 섞이지 않는다.

## 출력(향후)
- PDF를 100% 크기로 열어 오선과 기호가 깨지지 않는다.
- A4 페이지 경계 밖으로 악보가 잘리지 않는다.
- 가사와 음표가 겹치지 않는지 확인한다.
