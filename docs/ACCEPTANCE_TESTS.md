# 수용 테스트

## 프로젝트 파일

### 자동 테스트 (`ScoreStudio.Core.Tests`)
`dotnet test ScoreStudio.Core.Tests`로 실행한다. Windows가 아니어도 실행된다.
- 저장 후 다시 열었을 때 제목, 작곡가, 페이지 설정, 파트, 마디, 음표/쉼표(음높이, 길이, 위치, 철자, 가사)가 모두 같은지 비교한다.
- 같은 파일에 다시 저장해도 임시 파일이 남지 않는다.
- `samples/sample-choir.scoreproj`를 열 수 있다.
- 빈 파일, JSON이 아닌 파일, 중간에 끊긴 파일, 버전 정보가 없거나 너무 새로운 파일, 잘못된 박자·길이·음높이를 가진 파일을 열면 `ProjectFileException`과 한국어 오류 문구가 나온다.
- 열기에 실패한 파일은 내용과 수정 시각이 바뀌지 않는다.

### 수동 테스트 (Windows에서 앱 실행)
1. 새 프로젝트를 만들고 제목을 바꾼다.
2. `.scoreproj`로 저장한다.
3. 앱을 닫고 다시 실행한다.
4. 파일을 다시 열었을 때 제목과 파트가 보존되는지 확인한다.
5. 잘못된 JSON 파일을 열었을 때 앱이 종료되지 않고 오류를 안내하는지 확인한다. 오류 뒤에도 원래 열려 있던 악보가 그대로 남아 있어야 한다.
6. `samples/sample-choir.scoreproj`를 열었을 때 왼쪽 패널에 "소프라노", "피아노" 두 파트가 보이는지 확인한다.
7. 페이지 크기를 "A4 가로"로 바꾸어 저장하고 다시 열었을 때 "A4 가로"가 선택되어 있는지 확인한다.

## MUSX 가져오기(향후)
1. 원본 파일을 백업한다.
2. 변환 전 원본의 파트 수, 마디 수, 제목, 가사 유무를 기록한다.
3. 변환 후 같은 항목을 비교한다.
4. 임시표, 붙임줄, 이음줄, 반복기호, 셈여림, 아티큘레이션을 표본 검사한다.
5. 미지원 요소가 있으면 경고로 표시한다.
6. 원본 파일의 수정 시각/내용이 바뀌지 않았는지 확인한다.

## 편집(향후)
- 음표를 입력/삭제한 뒤 저장하고 다시 열어도 음악 정보가 유지된다.
- Undo/Redo가 편집 작업을 정확히 되돌린다.
- 박자에 맞지 않는 입력을 무시하거나 명확히 안내한다.
- 여러 파트의 음표가 서로 섞이지 않는다.

## 출력(향후)
- PDF를 100% 크기로 열어 오선과 기호가 깨지지 않는다.
- A4 페이지 경계 밖으로 악보가 잘리지 않는다.
- 가사와 음표가 겹치지 않는지 확인한다.
