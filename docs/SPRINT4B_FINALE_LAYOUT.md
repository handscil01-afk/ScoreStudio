# Sprint 4-1b — Finale 화면과 맞추기 설계와 수용 기준

## 배경
사용자가 「다윗의 노래」(4파트, 117마디)를 Finale 화면과 비교했을 때 다음 차이가 있었다.
- 피아노의 8va·8vb 구간이 실제 음높이로 그려져서 덧줄이 많이 생겼다.
- Finale에서 숨긴 빈 보표(테너 독창 1~26마디 등)가 모두 보였다.
- 원본의 줄 나눔·페이지 나눔을 따르지 않아서 35쪽이 되었다(Finale은 18쪽).
- 테너 독창의 옥타브 아래 높은음자리표와 피아노 왼손의 음자리표 변경이 반영되지 않았다.

## 데이터 모델 변경 (스키마 버전 4 → 5)
| 대상 | 추가 항목 | 설명 |
|---|---|---|
| `ScoreMeasure` | `ClefChanges` | `{Staff, PositionNumerator, PositionDenominator, Clef}` 목록. 그 위치부터 보표의 음자리표가 바뀐다. 위치가 0이면 마디 시작이다. |
| `ScoreMeasure` | `HiddenStaves` | 이 마디에서 숨긴 보표 번호(0부터) 목록. |
| `ScoreMeasure` | `SystemBreak`, `PageBreak` | 이 마디에서 새 줄 또는 새 페이지를 시작한다. |
| `ScoreEvent` | `OctaveShift` (기본 0) | 옥타브 기호 아래에 있는 음표: 1=8va, 2=15ma, −1=8vb, −2=15mb. `MidiPitch`와 철자는 실제 소리 그대로 두고, 화면에서만 옮겨 적는다. |

- 버전 1~4 파일은 그대로 열리고 새 항목은 비어 있는 값으로 채워진다. 저장은 버전 5로 한다.
- 잘못된 값(없는 보표 번호, 분모 0, 알 수 없는 음자리표, −2~2 밖의 옥타브 값)은 한국어 오류로 거절한다.

## 가져오기 규칙
- 파트에서 처음 나온 `clef`는 보표의 시작 음자리표로 쓰고, 그 뒤에 바뀐 `clef`는 그 시점(커서 위치)의 변경으로 기록한다. 같은 음자리표가 다시 나오면 기록하지 않는다.
- `octave-shift`는 시작·끝 지점을 시간 순서로 정렬한 뒤 그 사이에 시작하는 음표에 적용한다. `backup`으로 돌아간 두 번째 성부에도 적용된다.
- Finale은 `stop`을 옥타브 기호 아래 마지막 음표 바로 앞에 쓴다(「다윗의 노래」의 끝 지점 10곳 중 6곳에서 확인). 그래서 `stop`과 같은 시점에 시작하는 음표까지 옥타브 기호 안에 넣는다.
- `staff-details print-object="no"`는 그 마디부터 보표를 숨기고, `"yes"`는 다시 보이게 한다.
- `print new-system`/`new-page`는 첫 마디가 아닐 때만 기록한다.

## 화면 규칙
- **옥타브 기호**: 음표를 한 옥타브(15ma는 두 옥타브) 옮겨 적는다. 첫 음표 위(8vb는 아래)에 0.8배 크기의 `8va` 기호를 쓰고, 마지막 음표까지 점선을 그은 뒤 보표 쪽으로 짧은 갈고리를 내린다. 시스템이 바뀌면 다음 시스템에서 다시 쓴다.
- **숨긴 보표**: 시스템 안의 모든 마디에서 숨긴 보표는 그 시스템에서 빼고, 아래 보표를 위로 붙인다. 시스템마다 높이가 달라질 수 있다.
- **줄·페이지 나눔**: 원본의 줄 나눔이 있으면 그 구간을 한 줄에 넣는다. 음표 간격을 0.6배까지 줄여서 맞추고, 그래도 넘치면 자동으로 나눈다. 페이지 나눔이 있으면 새 페이지에서 시작한다. 원본에 줄 나눔이 없으면 이전처럼 자동으로 나눈다.
- **음자리표 변경**: 시스템 머리에는 그 시점의 음자리표를 그린다. 마디 시작의 변경은 마디선 바로 뒤(조표·박자표 앞)에, 마디 중간의 변경은 그 박의 음표 앞에 0.75배 크기로 그린다. 줄의 첫 마디에서 바뀌면 머리의 음자리표만 바꾼다. 바뀐 뒤의 음표와 조표는 새 음자리표 기준으로 놓는다.

## 수용 기준
### 자동 테스트 (`ScoreStudio.Core.Tests`)
샘플 `samples/musicxml/layout-features.musicxml`(직접 작성, 저작권 없음)에 마디 시작·중간 음자리표 변경, 숨긴 보표, 줄·페이지 나눔, 두 성부에 걸친 8va가 들어 있다.
1. 가져오기: 음자리표 변경 3개의 위치와 종류, 8va 구간의 음표 5개, 숨긴 마디, 줄·페이지 나눔이 원본과 같다. 경고가 없다.
2. 배치: 1번 줄은 1~2마디에 보표 1개, 2번 줄은 3~4마디에 보표 2개, 5마디는 2쪽에서 시작한다.
3. 음자리표: 2마디 앞과 4마디 셋째 박 앞에 작은 낮은음자리표가 그려지고, 2번 줄 머리는 높은음자리표다.
4. 8va: 실제 C6~F6가 C5~F5 자리에 적히고, 기호는 보표 위에 있으며, 점선은 4마디 전에 끝난다.
5. 저장 후 다시 열어도 새 항목이 보존되고, 버전 4 파일은 빈 값으로 열린다. 잘못된 값은 거절한다.

### Windows 화면 테스트 (`ScoreStudio.Tests`, CI)
- 새 샘플도 음자리표(작은 음자리표 포함)와 음표 머리가 레이아웃이 정한 자리에 그려지는지 확인한다. 작은 기호는 면적에 비례한 잉크 기준을 쓴다.

### 실제 파일 확인 (개발 환경에서 직접 그려 본 결과, 파일은 저장소에 넣지 않음)
- 「다윗의 노래」: 18쪽(Finale과 같음), 줄 구성도 Finale과 같다. 1쪽의 숨긴 보표와 8va, 4쪽의 테너 독창 음자리표가 맞게 나온다.

### 수동 테스트 (Windows PC)
1. 같은 파일을 가져와서 Finale 화면과 페이지 수, 줄마다의 마디, 숨긴 보표, 8va·8vb 구간, 음자리표 변경을 비교한다.

## 추가: 파트 이름 표시와 파트 묶음 (스키마 버전 6 → 7)
사용자의 실제 악보 3곡(「다윗의 노래」, 「하나님의 세계」, 「소원」)을 Finale 화면과 비교해서 찾은 차이다.
- 세 곡 모두 파트 이름이 `<part-name print-object="no">`로 숨겨져 있어서 Finale에는 이름이 없지만, ScoreStudio는 "파트 4"처럼 그렸다.
- 「다윗의 노래」는 성악 세 파트를, 「하나님의 세계」는 두 파트를 각진 괄호로 묶는다(`part-group`). 「하나님의 세계」는 마디선도 두 파트를 이어서 긋는다(`group-barline yes`).

| 대상 | 추가 항목 | 설명 |
|---|---|---|
| `ScorePart` | `ShowName` (기본 true) | 첫 줄 왼쪽에 이름을 그릴지. `part-name` 또는 `part-name-display`의 `print-object="no"`이면 false. 화면 왼쪽 "악보 구성" 목록에는 계속 보인다. |
| `ScoreProject` | `PartGroups` | `{FirstPart, LastPart, Symbol, JoinBarlines}` 목록. `Symbol`은 `None`, `Bracket`, `Brace`, `Line`, `Square`. |

- 가져오기: `part-group`의 `number`로 시작·끝을 짝지으며 겹친 묶음도 읽는다. 끝나지 않은 묶음은 마지막 파트까지로 맞추고 경고한다. `group-barline`이 `yes`일 때만 마디선을 잇는다(`Mensurstrich`는 잇지 않음).
- 화면: 묶음 기호는 피아노 중괄호보다 바깥에 그린다. 각진 괄호는 두께 0.5칸의 세로선과 Bravura의 위·아래 끝 기호(E003, E004)로 그린다. 숨긴 보표 때문에 묶음의 일부 파트만 보이는 줄에서는 보이는 보표만 묶는다. 파트 이름은 묶음 기호의 왼쪽에 쓴다.
- 버전 1~6 파일은 그대로 열리고, 모든 파트 이름을 표시하며 묶음은 없다.
- 자동 테스트: 샘플 `samples/musicxml/part-groups.musicxml`로 가져오기 결과, 괄호 위치, 이름 표시, 이어진 마디선을 검사한다. 겹친 묶음과 끝나지 않은 묶음은 별도 테스트로 검사한다. Windows 화면 테스트는 괄호 끝 기호에 잉크가 생기는지 확인한다.

## 추가: 원본의 페이지 배치 (스키마 버전 7 → 8)
「하나님의 세계」 1쪽이 Finale보다 훨씬 작고 촘촘하게 그려져서 아래 절반이 비었다. Finale은 보표 크기(이 곡은 1.99mm), 여백(20mm), 첫 줄 위치, 줄 사이·보표 사이 거리를 MusicXML에 적어 두는데, ScoreStudio는 1.75mm와 고정 간격을 썼다.

| 대상 | 추가 항목 | 설명 |
|---|---|---|
| `ScoreProject` | `Engraving` (없으면 기본 배치) | 보표 간격(mm), 네 방향 여백(mm), 기본 줄 간격·첫 줄 위치·보표 간격(칸) |
| `ScoreMeasure` | `SystemDistance`, `TopSystemDistance` | 이 마디에서 시작하는 줄의 앞 줄과의 거리, 페이지 첫 줄의 위 여백으로부터의 거리(칸) |
| `ScoreMeasure` | `StaffDistances` | 이 마디에서 시작하는 줄에서 이 파트 보표들의 위 보표와의 거리(칸) |

- 거리는 칸(staff space) 단위로 저장해서 보표 크기와 함께 늘고 줄어든다. 용지는 A4·Letter 중 가까운 것으로 정하고, 다른 크기는 A4로 표시하며 경고한다.
- 가져오기: `defaults`의 `scaling`이 없으면 배치 정보를 만들지 않는다(이전과 같은 기본 배치). Finale은 줄 간격을 그 줄의 맨 위에 보이는 파트에 적으므로, 줄 간격은 어느 파트에 있든 읽는다. 줄에 값이 없으면 `defaults`의 값을 쓴다.
- 화면: 페이지 첫 줄은 위 여백에서 원본 거리만큼 내려서 놓되, 1쪽에서는 제목 아래로 밀어낸다. 다음 줄은 앞 줄의 맨 아래 선에서 원본 거리만큼 띄운다. 보표 사이는 위 보표의 맨 아래 선에서 원본 거리만큼 띄우며, 숨긴 보표가 있으면 바로 위에 보이는 보표를 기준으로 한다.
- 아직 쓰지 않는 값: 줄 들여쓰기(`system-margins`, 예: 「다윗의 노래」 첫 줄). Finale의 마디 폭(`measure width`)은 스키마 14부터 쓴다(`docs/SPRINT4E_SOURCE_WIDTHS.md`).
- 자동 테스트: 샘플 `samples/musicxml/page-layout.musicxml`로 가져온 값과 줄·보표 위치, 페이지 수를 검사한다. 모든 악보 검사에 "원본 배치가 있으면 페이지 수가 원본의 페이지 나눔과 같고, 아래 여백을 넘는 줄이 없다"를 추가했다.
- 실제 악보(개발 환경, 저장소에 넣지 않음): 「다윗의 노래」 18쪽, 「하나님의 세계」 4쪽, 「소원」 2쪽(Letter)으로 원본과 같다.
